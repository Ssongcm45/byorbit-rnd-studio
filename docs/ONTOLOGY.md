# 온톨로지 · 시소러스 · 지식그래프 — 이 앱에서는 이렇게 씁니다

R&D Studio V0.5는 부산물 연구 용어를 **개념** 단위로 정리해 둡니다. 같은 것을 가리키는 여러 표기("사과박", "사과 포마스", "apple pomace")를 하나로 묶고, 개념끼리의 관계("사과박은 사과에서 나온다")를 기록합니다. 그래서 검색·라벨링·AI 답변·측정값이 모두 같은 말로 이어집니다.

## 세 가지 말의 뜻

| 말 | 이 앱에서의 뜻 | 예 |
|---|---|---|
| **온톨로지** | 개념을 어떤 **종류(체계·클래스)** 로 나누고, 개념 사이에 어떤 **관계**를 둘 수 있는지 정한 규칙 | 체계 9가지: 부산물·분류·원물·공정·성분·물성·단위·시험법·용도. 관계: 상위 분류(broader)·원료(derivedFrom)·발생 공정(generatedBy)·함유 성분(contains) |
| **시소러스** | 개념마다 **표준명** 하나와 **동의어**, **숨은 표기**를 모아 둔 용어 사전 | 사과박(표준명) = Apple pomace(영문 표준명) · 사과 포마스·사과 착즙박·apple marc(동의어) · 사과퍼미스(숨은 표기: 오타·옛 표기처럼 화면에는 내세우지 않지만 찾을 때는 쓰는 표기) |
| **지식그래프** | 개념(점)과 관계(선)에 **내 자료**(어느 문서가 그 개념을 언급했나)와 **측정값**(어느 부산물에서 무엇을 쟀나)까지 이어 붙인 지도 | 사과박 → 상위 분류 → 과실 착즙박, 사과박 → 함유 성분 → 식이섬유, 예시 논문 → 언급(9회) → 식이섬유, 사과박 → 측정(n=2, 평균 50.25 g/100 g) → 식이섬유 |

동의어는 따로 점을 만들지 않습니다. "사과 포마스"로 찾든 "apple marc"로 찾든 같은 **사과박** 점으로 모입니다.

## 어디에 있나

| 무엇 | 위치 |
|---|---|
| 표준 시드(원본) | `app/seed/seed_data.py` — 농·임·수산 분류 골격(TAXONOMY), 부산물 33종과 원물·발생 공정·주요 성분(BYPRODUCTS), 체계별 표준명·동의어(THESAURUS), 체계 → 클래스(SCHEME_CLASS) |
| DB 표 | `concept_scheme`(체계) · `onto_class`(클래스) · `concept`(개념, 표준명·IRI·시드/내 확장) · `concept_label`(표기: pref 표준명 / alt 동의어 / hidden 숨은 표기) · `concept_relation`(관계) · `byproduct`(부산물 사실표) |
| 지식그래프에 붙는 것 | `annotation.concept_id`(라벨 → 개념, 자료 언급 선의 근거) · `measurement.target_concept_id`·`byproduct_id`(측정 선의 근거) |
| 파일(SKOS 형식) | 데이터 폴더 `ontology\seed.ttl`(표준 시드, 앱이 만든 파일 — 직접 고치지 않음) · `ontology\mine.ttl`(내가 승인한 확장 개념이 쌓임) |
| 코드 | `app/db.py`(시드 적재·`SEED_VERSION`·TTL 만들기) · `app/thesaurus.py`(표기 → 개념, 동의어 확장, 사전 라벨링) · `app/routes_kg.py`(지식그래프 API) · `app/static/kg/`(지식그래프 화면) |

IRI(개념의 고유 주소)는 `https://byorbit.kr/onto/…` 형식입니다. 예: 사과박 = `https://byorbit.kr/onto/Byproduct/apple-pomace`. 내 확장은 `https://byorbit.kr/onto/mine/…`.

## 어떻게 쓰이나

1. **동의어 확장 검색** — 검색 탭에서 "사과 포마스 TDF"를 찾으면 사과박의 모든 표기와 식이섬유의 모든 표기(총식이섬유·dietary fiber…)로 넓혀 찾습니다.
2. **사전 라벨링** — 자료를 넣으면 본문에서 시소러스 표기를 찾아 개념 라벨을 미리 붙입니다(긴 표기 먼저, 영문 약어는 단어 경계를 지킴). 이 라벨이 지식그래프의 "언급" 선이 됩니다.
3. **AI의 표준명 확인** — Claude Code·Codex는 자료 서버의 `lookup_concept` 도구로 용어의 표준명과 동의어를 먼저 확인한 뒤 자료를 찾습니다. 그래서 답변이 같은 이름을 씁니다.
4. **학습한 동의어** — 문서 작업대에서 모르던 표기를 "동의어로 배우기" 하면 그 개념의 동의어(alt)로 들어가, 다음부터 검색·사전 라벨링에 바로 쓰입니다. 사람이 거절한 사전 라벨은 같은 문맥에서 다시 붙이지 않습니다.
5. **측정값 연결** — CoA에서 읽은 값과 승인한 추출값은 부산물 개념과 측정 항목 개념(예: 식이섬유)에 연결됩니다. 지식그래프의 "측정" 선은 이것을 묶어 값 개수·평균·범위를 보여 줍니다. 시료의 로트·공급처는 그래프에 싣지 않습니다.

## 지식그래프 화면 읽는 법

개념 탭 → **지식그래프**. 처음에는 사과박이 가운데에 있습니다.

- 점 색 = 체계, 네모 = 자료(문서), 점선 테두리 = 보이지 않는 이웃이 더 있음.
- 선 = 상위 분류 · 원료 · 발생 공정 · 함유 성분 · 측정 · 언급 · 기타 관계. 선 칩으로 켜고 끕니다.
- 점을 누르면 옆에 자세히(표준명·영문·동의어·숨은 표기·체계·IRI·관계·언급 자료·측정값 요약), 두 번 누르면 그 개념이 가운데로 옵니다. 깊이 2단계는 이웃의 이웃까지 보여 줍니다(최대 150개 점).
- 그림 아래 **이웃 목록**은 같은 내용을 키보드로 볼 수 있는 목록입니다.

## 늘리는 법

- **새 개념**: 개념 탭 → 분류·목록 → **+ 개념 추가**. 표준명·체계·동의어·상위 개념을 넣으면 내 확장(origin=mine)으로 들어가고 `mine.ttl`에 쌓입니다. AI가 `propose_concept`로 제안한 개념은 목록에서 **승인**해야 검색·라벨링·지식그래프에 쓰입니다(그래프에는 흐리게 보임).
- **새 동의어**: 문서 작업대 라벨 탭에서 본문을 골라 **동의어로 배우기**.
- **표준 시드 자체를 고칠 때**(개발자): `app/seed/seed_data.py`를 고치고 `app/db.py`의 `SEED_VERSION`을 올립니다. 다음 시작 때 빠진 개념·동의어·관계만 더하고, 기존 개념과 내 확장은 그대로 둡니다.

## 내보내기

- 지식그래프의 **TTL 내보내기** → `rd-studio-ontology.ttl`. 표준 시드와 승인한 내 확장을 SKOS(`skos:prefLabel`·`altLabel`·`hiddenLabel`·`broader`)와 `byo:derivedFrom`·`byo:generatedBy`·`byo:contains`로 한 파일에 담습니다. Protégé, Skosmos, TopBraid 같은 도구에서 열 수 있습니다. 파일 두 개를 이어 붙이지 않고 지금 DB에서 새로 만들므로 작업대에서 배운 동의어까지 들어갑니다.
- **JSON 내보내기** → `rd-studio-knowledge-graph.json`. 점(개념·자료)과 선(관계·언급·측정) 목록입니다. PC 밖으로 옮겨질 수 있는 파일이라 기밀 자료 이름은 `기밀자료-xxxxxx`로 가리고, 기밀 자료·시료의 측정값은 넣지 않습니다.
- 데이터 폴더의 `ontology\seed.ttl`·`mine.ttl`도 그대로 쓸 수 있습니다.
