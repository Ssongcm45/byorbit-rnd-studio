# 통계 분석 — 회귀·t검정·가정 점검·논문용 표와 그림

"수율에 온도·반응 시간·산 종류가 주는 영향"을 회귀분석하고, "산 종류별 수율 차이"를 t검정한다.
가정 점검 결과, 논문용 **표 1개**(표 1), **그림 1장**(그림 1), **해석 세 문장**을 만들고, 같은 숫자를 Python·R·Stata로 다시 낼 수 있는 파일을 함께 준다.
모든 계산은 이 PC 안에서만 한다(밖으로 보내는 길 없음).

- 코드: `app/stats/`(data·core·analysis·report·export·fmt), API `app/routes_stats.py`(`/api/stats`), 화면 `app/static/stats/stats.js`
- 단독 확인 페이지: `/static/stats/dev.html?demo=2|3&exp=<실험 ID>&run=1&lang=en&theme=dark`
- 시험: `tests/test_stats.py`

## 1. 쓰는 법

1. **데이터 고르기**
   - **내 실험**: 런 하나가 한 행. 조건(단계별 값 — 런에 비운 칸은 흐름 값으로 채우고 알려 줌), 내가 잰 값(ND·`< x` 처리), 런 비고의 꼬리표가 변수가 된다.
     **범주 조건**(추출 단계의 `산 종류`·`용매 종류`, 건조 단계의 `건조 방식`)은 자동으로 범주 변수(`acid`·`solvent`·`method`)가 된다 — 실험 데이터 탭의 조건 칸에 런마다 넣는다(목록에서 고르거나 직접 입력, CSV·XLSX의 `산`·`acid`·`산 종류`·`용매`·`solvent` 열도 같은 칸으로 읽음).
     예전 방식인 **런 비고 꼬리표 `산=구연산; 반복=2`도 그대로 읽는다**: 같은 이름의 조건(예: `acid`)이 있으면 그 런의 조건 칸이 빌 때 꼬리표 값을 쓴다(런 조건 > 비고 꼬리표 > 흐름 값 — 꼬리표로 채운 칸 수를 알려 줌).
     구연산·염산·질산·황산·옥살산·초산·젖산·사과산은 R·Stata용 영문 코드(citric, HCl, nitric …)로, 용매(물·에탄올·에탄올 수용액 …)와 건조 방식(열풍건조 → hot_air …)도 영문 코드로 바뀐다(한국어 이름은 코드북).
     실측 대상 `수율`·`펙틴 수율`(제품 수율)은 `product_yield`(%)로 들어오고 결과 변수 후보 1순위가 된다(`체 통과 수율`은 `sieve_yield`).
   - **파일**: CSV(UTF-8·CP949)·XLSX. 열 이름으로 이름·형식(연속·범주·런 이름)을 짐작하고, '열 대응'에서 고친다. 파일은 메모리에만 1시간 둔다.
   - **예시**: 사과박 펙틴 산 추출 수율 — **가짜(모의) 데이터**. 3 온도(70·80·90 ℃) × 3 시간(60·90·120 min) × 산(구연산·염산, 또는 + 질산) × 반복 3, 고정 시드.
     모의에 쓴 참값: 수율 = 13.8 + 0.16·(T − 80) + 0.008·(t − 90) + 산 효과(염산 +1.9, 질산 +1.1) + N(0, 1.0²) %. 한 런(CIT-90-120-r3)은 결측 처리 예시로 비워 두었다.
     화면·표·그림·묶음 모두에 '예시(모의) 데이터'가 찍힌다.
2. **변수 역할**: 결과(연속, 예: 수율) · 연속 설명 변수(온도·시간) · 범주 설명 변수(산 종류) + 기준 수준 · 집단 비교 변수 · t검정 종류(Welch 기본) · α.
   **모형 항(선택, 기본 꺼짐 = 주효과만)**: 설명 변수 두 개의 **교호작용**(예: 온도 × 산 종류 — 연속×범주·연속×연속·범주×범주)과 연속 변수의 **2차항**(값이 3가지 이상일 때).
   **그림 1 가로축**: 연속 설명 변수 중에서 고른다(기본: 이름이 temp로 시작하는 것 → 첫 연속 변수).
3. **분석 실행** → 결과: 가정 점검 카드, 표 1(학술지 형식 미리보기), 그림 1, 해석 세 문장(한·영), 보조 진단 그림, 방법 문장.
4. **내보내기**: 파일마다, 또는 '논문용 묶음 받기'(ZIP).

변수 이름은 R·Stata에서 그대로 쓰도록 영문 소문자 snake_case 32자 이하(`yield_pct`, `temp_c`, `time_min`, `acid`). 한국어 이름·단위·수준은 코드북에 있다.

## 2. 검정이 하는 일

| 분석 | 무엇 | 보고 |
|---|---|---|
| 다중 선형 회귀(OLS) | 수율 = b0 + b1·온도 + b2·시간 + b3·[산 = 염산] (+ …). 범주는 기준 수준 대비 가변수. 고르면 + b4·(T − T̄)² + b5·(T − T̄)·[산 = 염산] … — 곱항·2차항의 연속 변수는 분석 표본 평균으로 중심화하고 주효과 열은 그대로 둔다(주효과 B = 다른 연속 변수의 평균·범주의 기준 수준에서의 기울기·차이) | B, SE, β(연속 변수만, B·SD(x)/SD(y)), t, p, 95% CI, R², 수정 R², F(df1, df2), p, n, RMSE(잔차 표준오차). 3수준 이상 범주는 항 전체 F 검정 |
| HC3 강건 SE | 이분산에도 맞는 표준오차 | 늘 계산. Breusch–Pagan p < α이면 **표 1의 주 결과를 HC3로** 바꾸고 각주·해석에 밝힌다 |
| 집단 비교(2수준) | **Welch t-검정(기본)** — 등분산 가정 없음. 선택: Student(등분산), 자동(Levene p < α면 Welch) | 집단별 n·평균 ± SD, t(df), p(양측), 차이(비교 − 기준)와 95% CI, Cohen's d·Hedges' g, Mann–Whitney U(민감도) |
| 집단 비교(3수준 이상) | t검정 하나로는 셋 이상을 비교할 수 없다 → **Welch 일원분산분석**(기본; Student 선택 시 고전 ANOVA) 후 **모든 쌍을 Welch t-검정하고 Holm 보정** — 이것이 3수준 이상에서의 't검정' | F(df1, df2), p, η²·ω²(고전), 쌍별 차이·t(df)·Holm p·g, Kruskal–Wallis(민감도) |

**t검정과 회귀의 산 효과가 다른 이유**: t검정은 온도·시간을 무시한 단순 평균 차이(주변 차이), 회귀 계수는 온도·시간을 같게 놓았을 때의 차이(보정 효과)다.
균형 설계(모든 조건 조합에 산마다 같은 수의 런)면 둘이 거의 같고, 불균형이면 달라진다. 회귀는 온도·시간이 설명하는 변동을 빼므로 대개 더 정밀하다. 결과 화면에 두 값을 나란히 보인다.

**결측**: 분석에 쓰는 변수 중 하나라도 빈 런은 회귀와 집단 비교 모두에서 뺀다(목록별 삭제 — 두 분석이 같은 표본). 뺀 런과 이유(빈칸·ND·검출 한계·숫자 아님)를 보이고 방법 문장·표 주석에 수를 적는다.
검출 한계(`< x`)는 기본으로 결측이고, '한계값'·'한계의 1/2'로 바꿀 수 있다(바꾸면 그 사실을 논문에 밝혀야 한다).

## 3. 가정 점검과 기준

판정: **통과**(위반 근거 없음) · **주의** · **실패** · **설계로 판단**(자료로 검정할 수 없음). 모든 판정에 검정 이름·통계량·n·기준값을 함께 보인다.
검정이 유의하지 않다는 것만으로 '가정이 맞다'고 쓰지 않는다 — n < 30(잔차)·집단 n < 15이면 "검정력이 낮아 위반 없음을 보장하지 않는다"를 붙인다.

| 점검 | 검정 | 기준 |
|---|---|---|
| 잔차 정규성 | Shapiro–Wilk + Q–Q 그림 | p ≥ .05 통과. p < .05이면 n ≥ 30 주의(계수 추정은 비교적 견고) · n < 30 실패 |
| 등분산(잔차) | Breusch–Pagan(Koenker 학생화, 설명 변수 전체) + 잔차-적합값 그림 | p ≥ .05 통과 · p < .05 실패 → HC3 주 결과 |
| 다중공선성 | VIF(3수준 이상 범주는 GVIF^(1/(2·df))의 제곱). 곱항·2차항의 값도 보이지만 판정은 주효과 항으로만 | ≤ 5 통과 · 5–10 주의 · > 10 실패 |
| 영향점 | Cook's D | 4/n 넘는 런을 런 이름으로 나열(주의) · D > 1 실패. 빼려면 측정 오류 근거가 있어야 하고 논문에 밝힌다 |
| 선형성 | 중심화 2차항을 더한 t검정(값이 3개 이상인 연속 변수) + 잔차-변수 그림. 2차항을 모형에 넣은 변수는 따로 검정하지 않는다(계수표의 2차항이 그 검정) | p ≥ .05 통과 · < .05 주의 |
| 독립성 | 자료로 증명 불가 — 설계로 판단(런 순서 무작위화, 반복이 서로 다른 추출인지). `run_order` 열이 있으면 실험 순서 Durbin–Watson | DW 1.5–2.5 밖이면 주의 |
| 표본 크기(회귀) | n ÷ 설명 계수 수 | ≥ 10 통과 · 5–10 주의 · < 5 실패 |
| 표본 크기(집단) | 가장 작은 집단 n | ≥ 10 통과 · 5–9 주의 · < 5 실패 |
| 집단별 정규성 | 집단별 Shapiro–Wilk | 모두 p ≥ .05 통과 · 아니면 비모수 검정을 민감도로 보고 |
| 등분산(집단) | Levene(중앙값 기준 = Brown–Forsythe) | p ≥ .05 통과. Welch를 쓰면 위반이어도 '주의'(결과 유효), Student면 '실패' |

## 4. 표·그림·문장의 표기

- **표 1**(한 표): 패널 A 회귀(변수 | B | SE | β | t | p | 95% CI, 아래에 R²·수정 R²·F·n·RMSE·모형·SE 종류), 패널 B 집단 비교(산 종류 | n | M ± SD | t(df) | p | Hedges' g | Δ [95% CI];
  3수준 이상은 p가 Holm 보정값이고 기준 밖 쌍도 한 줄씩). 가로줄은 표 위·머리글 아래·표 아래만(세로줄 없음). DOCX(Times New Roman/맑은 고딕)·HTML·CSV·LaTeX(booktabs)·Markdown.
- **숫자**: APA 7 — p는 소수 셋째 자리, `p < .001`, 반올림하면 .050이 되는 .0495 ≤ p < .05는 넷째 자리(.0497). B·SE·CI의 소수 자리는 SE 크기에 맞춘다. 음수는 '−'.
  1을 넘지 않는 값(p, R², β)의 앞 0: 영어 APA는 뺌(.034), 한국어는 씀(0.034) — '숫자 앞 0'에서 바꿀 수 있다.
- **그림 1**(한 장): (a) 수율 vs 고른 가로축(기본 온도), 산별 색·표식(Okabe–Ito, 색각 이상에도 구분) + 모형 예측선(다른 연속 변수는 평균, 교호작용·2차항을 넣으면 산마다 기울기가 다르거나 곡선), (b) 산별 상자 + 점 + 평균 ± 95% CI(검은 마름모)와 t검정(3수준은 Holm 쌍별 p) 표시.
  300 dpi PNG·SVG·PDF, 폭 1단 85 mm(두 패널 위아래)·2단 175 mm(좌우). 한국어 맑은 고딕, 영어 Arial. 그림 설명(캡션)을 함께 준다. 잔차 진단 그림은 **보조 그림 S1**(그림 1에 세지 않음).
- **해석 세 문장**(한·영, AI 생성 아님 — 숫자로 채우는 틀 문장): (1) 모형 적합(R², F, p, n), (2) 연속 설명 변수(유의한 것은 방향·크기 B·95% CI·p, 아닌 것은 '유의하지 않음'), (3) 산 종류 차이(t검정 결과 + 회귀의 보정 효과; 3수준은 Welch ANOVA → Holm 쌍별 → 보정 효과).
  잔차 정규성 실패·영향점 실패·작은 표본·곡선 가능성·이분산·작은 집단이 있으면 같은 문장 안에 단서("잠정적으로 해석", "검정력 낮음")를 자동으로 붙인다.

## 5. Python·R·Stata 재현 파일

`재현 패키지 ZIP`(묶음 안 `reproduce/`): `data.csv`(UTF-8 BOM, ASCII 열 이름, 결측 = 빈칸) · `codebook.csv` · `analysis.py` · `analysis.R` · `analysis.do` · `README.txt` · `app_results.json`(앱의 숫자).

- **교호작용·2차항**: R·Stata 스크립트가 앱과 같은 열(`sq_<변수>` = (x − x̄)², `ix<n>_<a>_<b>` = (x − x̄)·[수준]·…)을 분석 표본(목록별 삭제 뒤) 평균으로 직접 만들어 회귀에 넣는다. 열과 앱 항 이름의 대응은 README.txt에 적는다.
- **Python**: `pip install numpy pandas scipy statsmodels` → `python analysis.py`. 앱의 `app/stats/core.py`를 글자 그대로 넣은 스크립트라 같은 버전이면 **같은 숫자**가 나온다(시험에서 실제로 실행해 B·p 차이 < 1e-8 확인).
- **R**: 작업 폴더를 그 폴더로 → `source("analysis.R", echo = TRUE)`. `lm(yield_pct ~ temp_c + time_min + acid)`, `factor(acid, levels = c(기준, …))`, `summary`·`confint`, 표준화 β, HC3(직접 계산), `shapiro.test`, `lmtest::bptest`(없으면 직접), `car::vif`, Cook's D, 2차항, `car::leveneTest`(없으면 직접),
  `t.test(var.equal = FALSE)` · `wilcox.test` 또는 `oneway.test` · `pairwise.t.test(p.adjust.method = "holm", pool.sd = FALSE)` · `kruskal.test`, ggplot2 그림(있으면).
- **Stata**(15 이상): `do analysis.do`. `import delimited` → `encode acid`(기준 = 1) → `regress yield_pct temp_c time_min ib1.acid_f`, `estat hettest, rhs iid`, `estat vif`, `, beta`, `vce(hc3)`, `predict r, resid` · `swilk r`, Cook's D,
  `robvar`, `ttest …, by(acid_f) unequal`, `esize`, `ranksum` 또는 `oneway`·`kwallis`·쌍별 Welch + Holm(Mata), `graph combine`·`graph export`.

**주의 — R·Stata 스크립트는 실행해 보지 않았다.** 이 PC에 R·Stata가 없어 표준 명령만 써서 보수적으로 만들었다. 처음 돌릴 때 `app_results.json`과 비교할 것. 알려진 차이:

- t검정 부호: 앱·Python은 '비교 − 기준', R `t.test`·Stata `ttest`는 '기준 − 비교'(p는 같다).
- Levene: 앱·R `car::leveneTest`는 중앙값 기준 = Stata `robvar`의 W50.
- Breusch–Pagan: 앱 = R `lmtest::bptest` 기본 = Stata `estat hettest, rhs iid`(모두 Koenker 판). Stata `estat hettest` 기본(적합값·정규 가정)과는 다르다.
- VIF: 3수준 이상 범주에서 앱·R은 항별 GVIF, Stata는 가변수별 VIF.
- Shapiro–Wilk: Stata `swilk`는 근사식이 달라 p가 조금 다를 수 있다.
- Welch ANOVA: Stata 기본 명령 없음(`ssc install wanova`). 쌍별 Welch + Holm은 do 파일이 직접 계산한다.
- Mann–Whitney: 앱 U = 비교 수준의 U, R `wilcox.test`의 W = 기준 집단의 U(= n1·n2 − U). 둘 다 점근 근사 + 연속성 보정.

## 6. 한계

- 교호작용·2차항은 사용자가 고를 때만 넣는다(기본은 주효과만). 자동 모형 선택(단계적 선택 등)은 하지 않는다 — 항을 늘리면 계수당 n이 줄어드니 표본 크기 점검을 본다.
  해석 둘째 문장 끝에 추가 항의 결과를 붙이고(문장 수는 셋 그대로), 곱항이 있으면 주효과가 '평균·기준 수준에서의 값'임을 밝힌다.
- 반복이 같은 추출물의 반복 측정(기술 반복)이면 독립성이 깨진다 — 런 평균을 내거나 혼합 모형을 써야 한다(이 기능 밖).
- 산 종류·용매 종류는 기록·통계 분석용이다 — 내 실험의 추출 예측 모델은 산·용매의 효과를 계산하지 않는다(근거 없음, 추출 단계에 안내가 뜬다). 산별 차이는 이 통계 분석으로 본다.
- 가정 점검 카드·보조 표 S1은 언어가 English이면 검정 이름·통계량·기준까지 영어로 보인다. 화면의 다른 안내 글은 한국어다.
