# 문서 작업대 — 청크 검사·고치기, 규칙 배우기, 라벨(사람·사전·AI)

자료함의 자료 줄에서 **작업대**를 누르면 열립니다. 검색 결과(“작업대에서 열기”)와 라벨 검토 줄(“작업대”)에서 열면 그 청크로 바로 갑니다.
탭은 네 개입니다: **파싱 · 청크 · 라벨 · 배운 것**.

배우는 방식은 **규칙·사례 학습**입니다. 모델을 다시 학습(미세조정)시키지 않습니다. 고친 것에서 규칙·동의어·사례를 만들고,
배운 것은 모두 “배운 것” 탭에서 보고 끄거나 지울 수 있습니다. 모두 이 PC의 DB에만 있습니다.

## 1. 파싱 탭
파서 도구 고르기·다시 파싱·나란히 비교 화면입니다(파서 묶음 `parse.js`). 설치되어 있지 않으면 “파서 도구 준비 중”이 보이고
나머지 탭은 그대로 쓸 수 있습니다. 다시 파싱하면 청크가 새로 만들어지고, 켜 둔 청크 규칙이 자동으로 다시 적용됩니다.
사람이 붙인 라벨과 승인한 라벨은 새 청크의 같은 표기로 옮겨집니다.

## 2. 청크 탭 — 검사하고 고치기
왼쪽은 읽는 순서대로 본 청크 목록(쪽·섹션 제목·본문/표·글자 수·라벨 수·문제 표시), 오른쪽은 고치는 칸입니다.
“문제 있는 것만”을 켜면 표시가 붙은 청크만 보입니다.

| 표시 | 뜻 | 어떻게 |
|---|---|---|
| 짧음 / 김 | 기본 80자 미만 / 1,920자 초과(길이 규칙이 있으면 그 값) | 합치기 / 커서에서 나누기 |
| 끊김 | 문장이 끝나지 않은 채 다음 청크(같은 섹션)로 넘어감 | 다음과 합치기 |
| 표 나뉨 | 표 하나가 여러 청크로 나뉨 | 합치기, 또는 ‘표 묶기’ 규칙 |
| 잡음 | 쪽 번호(“- 3 -”, “p. 3”)나 여러 청크에 되풀이되는 줄(머리글·바닥글) | 줄 옆 “지우기” 또는 “커서 줄 지우기(잡음)” |
| 중복 | 다른 청크와 본문이 같음 | 한쪽을 “청크 지우기(잡음)” |
| OCR 낮음 | 글자 인식 신뢰도가 0.8 미만(파서가 값을 남긴 경우) | 원본과 대조해 글 고치기 |
| 라벨 확인 | 위치를 잃은 사람 라벨이 있음 | 라벨 탭에서 자리 다시 잡기 |

고치는 방법(본문 칸의 **커서 위치·커서가 있는 줄**이 기준):
- **글 저장** — 본문을 고칩니다.
- **커서에서 나누기** — 두 청크로 나눕니다. 뒤 조각에도 섹션 제목 줄이 붙습니다. 앞 조각은 원래 청크 id를 그대로 씁니다(리포트 근거 유지).
- **이전과 / 다음과 합치기** — 겹친 섹션 제목 줄과 표 머리글은 한 번만 남깁니다. 리포트 근거·라벨 사례 연결도 함께 옮깁니다.
- **커서 줄을 제목으로** — 그 줄부터 다음 섹션 전까지가 새 섹션이 됩니다.
- **커서 줄 지우기(잡음)** — 같은 줄이 여러 번 있으면 모두 지웁니다. 섹션 제목 줄은 지우지 않습니다.
- **청크 지우기(잡음)**, **종류**(본문·표), **섹션**(다른 섹션으로 옮기기 또는 새 섹션).
- **되돌리기**(위쪽) — 이 자료의 마지막 작업부터 하나씩 되돌립니다. 규칙 적용은 한 번에 되돌아갑니다.
  다시 파싱(다시 청킹)한 뒤에는 그 전 작업을 되돌릴 수 없습니다(청크가 통째로 바뀌기 때문).

모든 변경은 전문검색 색인에 바로 반영되고 변경 기록(change_log)에 남습니다.

### 라벨은 어떻게 되나
- 글을 고쳐도 표기가 그대로 있으면 라벨 위치를 옮깁니다. 나누기·합치기에서는 라벨이 따라갑니다.
- 사전·AI 라벨의 표기가 사라지면 그 라벨은 지우고, 무엇을 지웠는지 화면에 보여 줍니다.
- **사람이 붙였거나 승인한 라벨은 절대 조용히 지우지 않습니다.** 표기를 찾지 못하면 라벨은 남기고 위치만 비워
  “위치 확인 필요”로 표시합니다(측정값 연결도 그대로). 그런 라벨이 있는 청크를 지우려 하면 먼저 묻고, “그래도 지우기”를
  고르면 라벨을 이웃 청크로 옮깁니다.

## 3. 규칙 배우기와 범위
잡음 줄을 지우거나, 줄을 제목으로 올리거나, 짧은 조각을 합치거나, 긴 청크를 나누면 청크 탭 아래 **규칙 배우기**에 후보가 생깁니다.

| 규칙 | 배우는 곳 | 하는 일 |
|---|---|---|
| 잡음 줄 | 지운 줄(숫자는 아무 숫자로 일반화. “- 3 -” → “- n -”) | 같은 모양의 줄을 지움 |
| 제목 줄 | 제목으로 올린 줄(“2. 재료 및 방법” → “번호. 글” 꼴, 마침표로 끝나는 문장·수치 줄은 제외) | 같은 꼴의 줄을 섹션 제목으로 |
| 짧은 조각 합치기 | 짧은 조각을 합친 횟수·길이 | 그보다 짧은 본문 조각을 앞 청크에 붙임 |
| 표 묶기 | 같은 표의 청크를 합친 것 | 같은 표 청크를 하나로, 다시 파싱 때 표를 나누지 않음 |
| 청크 길이 | 긴 청크를 나눈 것 | 다시 파싱 때 청커 목표 크기, 너무 긴 청크 나누기 |

규칙으로 저장할 때 **범위**를 고릅니다(좁은 것이 우선):
이 자료만 · 파일 이름 꼴(예: `시험보고서_*_*.txt`) · 제목 앞부분(같은 출처) · 같은 형식(예: 모든 PDF) · 모든 자료.

- **미리보기** — 적용하면 어디가 바뀌는지 보여 줍니다(저장하지 않음).
- **이 자료에 적용** — 켜진 규칙 중 범위가 맞는 것을 적용합니다. 되돌리기 한 번에 모두 되돌아갑니다.
- 다시 파싱할 때는 자동으로 적용됩니다(청커 크기·표 처리 값도 규칙을 따름).
- 규칙은 “배운 것” 탭에서 켜기·끄기·고치기(정규식·값)·지우기를 할 수 있고, 몇 번 적용됐는지·어느 자료에 썼는지 보입니다.
  “규칙 직접 만들기”로 처음부터 만들 수도 있습니다.

## 4. 라벨 탭 — 사람 라벨과 자동 라벨
본문에 붙은 라벨이 종류별 색으로 보입니다(실선 = 승인·사람, 점선 = 검토 대기·자동). 위 범례를 보세요.

**사람 라벨**
1. 본문에서 글을 선택하고 **L**(또는 “선택에 라벨”). 키보드만 쓸 때는 “표기로 붙이기”에 본문 글자를 그대로 넣고(같은 표기가 여러 번이면 몇 번째인지) “라벨”.
2. 창에서 종류를 고르고, 개념을 표준명·동의어로 찾아 고릅니다. 맞는 개념이 없으면 체계를 골라 “새 개념으로”(내 확장).
3. 수치(VALUE)는 값·단위·기준(건량·습량)·항목을 선택한 글과 앞 문장에서 미리 채워 줍니다.
4. 저장하면 바로 **승인**된 사람 라벨이 되고, 수치는 라벨 검토에서 승인할 때와 같은 방식으로 **측정값 표**에 올라갑니다.

오른쪽 목록에서 승인·거절·되돌리기·고치기·지우기를 합니다. 단축키는 라벨 검토와 같습니다:
**J/K** 이동 · **A** 승인 · **R** 거절 · **L** 선택에 라벨 · **E** 고치기 · **[ / ]** 이전·다음 청크(입력칸에 쓰는 중에는 동작하지 않음).

**자동 라벨**
- **사전 라벨 다시**(자료 전체·이 청크) — 지금 시소러스(배운 동의어·부정 사례 포함)로 다시 붙입니다. 사람이 승인·거절한 사전 라벨,
  사람·AI 라벨은 그대로 두고, 그 자리와 겹치는 표기는 건너뜁니다.
- **AI 라벨**(자료 전체·이 청크) — Claude Code 라벨러를 돌립니다. 진행 막대가 보이고, 수치 제안은 검토 대기로 옵니다.

## 5. 라벨 수정에서 배우는 것
- **동의어** — 사전이 모르는 표기에 개념을 붙이면 “동의어로 배우기”를 권합니다. 확인하면 그 개념의 동의어(내 확장)가 되어
  사전 라벨·검색이 바로 이 표기도 찾습니다. 배운 동의어는 `데이터 폴더\ontology\mine.ttl`에도 `skos:altLabel`로 들어갑니다
  (`db.regenerate_mine_ttl()` — 내 확장 개념 + 시드 개념에 더한 동의어로 파일을 DB에서 다시 만듦, 직전 내용은 `mine.ttl.bak`).
- **부정 사례** — 사전 라벨을 거절하면(또는 지울 때 배우기를 고르면) “이 문맥에서 이 표기에 이 개념을 붙이지 말 것”을 배웁니다.
  같은 문맥 = 바로 앞 낱말이나 뒤 낱말이 같은 경우. “배운 것”에서 **어디서나**로 넓히거나 끌 수 있습니다. 거절을 되돌리면 그 부정 사례는 꺼집니다.
  사전 라벨을 고쳐 다른 개념으로 바꿔도 옛 개념에 대한 부정 사례가 생깁니다.
- **라벨 사례** — 사람이 붙인 라벨과 고친 사전·AI 라벨은 사례로 남습니다. AI 라벨을 돌릴 때 지금 청크와 관련 높은 사례
  (같은 개념 > 같은 부산물 > 같은 라벨 종류) **최대 8개**를 라벨러 프롬프트 끝의 “참고 사례” 절로 붙입니다(부정 사례는 2개까지).

## 6. AI로 무엇이 나가나
- AI 라벨을 돌리면 청크 본문(라벨러가 도구로 읽음)과 **참고 사례**가 Anthropic(설정에 따라 Codex)으로 전송됩니다.
- 사례 중 **기밀** 자료에서 나온 것은 설정의 CoA 규칙을 따릅니다.
  - **가림(mask)**: 로트번호·공급처·시료번호를 `[가림]`으로 바꿔 보냅니다. 표기 자체가 가려지는 사례는 아예 뺍니다.
  - **보내지 않기(block)**: 기밀 사례를 보내지 않습니다. Codex로 돌릴 때는 설정과 관계없이 늘 보내지 않습니다.
- 라벨 탭의 **“AI에 보낼 사례 보기”** 로 보낼 내용을 그대로 미리 볼 수 있습니다.
- 사례를 끄거나 지우면 다음 실행부터 빠집니다. 청크 규칙·동의어·부정 사례는 밖으로 나가지 않습니다(이 PC 안에서만 씀).

## 7. 배운 것 끄기
“배운 것” 탭에 네 가지가 있습니다: 청크 규칙 · 배운 동의어 · 부정 사례 · 라벨 사례.
각각 켜기·끄기(체크) 또는 지우기를 할 수 있고, 끄면 바로 쓰이지 않습니다. 배운 동의어 지우기는 작업대에서 배운 것만 되며(지우면 mine.ttl도 다시 만들어 그 altLabel이 빠짐),
시드·직접 만든 표기는 개념 화면에서 관리합니다.

## 8. 라벨 검토 화면에서 부정 사례 배우기(API 준비됨)
라벨 검토 화면(server.py `/api/annotations/{id}`)은 지금 배우지 않습니다(learn=False). 설정 없이 호출마다 고를 수 있는 길:
`POST /api/wb/labels/{ann_id}/review` 본문 `{"status": "rejected", "learn": true}` — 거절한 사전 라벨을 부정 사례로 배우고,
`{"status": "pending", "learn": true}`(되돌리기)는 그 거절로 배운 부정 사례를 끕니다. `learn: false`면 라벨 검토 화면과 똑같이 동작합니다.
응답: `{ok, measurement_id, removed_measurements, negative_example?, negatives_disabled?}`. 이미 규칙으로 바꾼 청크는 규칙을 지워도 그대로입니다(되돌리기로 되돌림).
