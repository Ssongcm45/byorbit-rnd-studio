# 기술 지도

프로그램은 여러 층으로 쌓여 있습니다. 건물로 치면 1층은 창고, 2층은 사무실, 3층은 손님을 맞는 창구입니다. 이 장에서는 층마다 어떤 기술이 무슨 일을 하는지, 그리고 **왜 그 기술을 골랐는지** 봅니다. 코드를 몰라도 괜찮습니다. 코드 조각마다 쉬운 말 풀이를 붙였습니다.

### 층으로 보는 구조

![기술 층과 층마다 하는 일](i03-architecture.png "출처: 송창민 작성")

위에서 아래로 읽어 봅시다.

1. **브라우저 화면** — 우리가 보고 누르는 곳입니다. 크롬이나 엣지에서 열립니다.
2. **서버** (FastAPI) — 화면이 보낸 요청을 받아 일을 처리합니다. 내 PC 안에서만 돕니다.
3. **데이터베이스와 데이터 폴더** (SQLite) — 자료와 라벨과 측정값을 저장합니다.
4. **MCP 서버** — AI가 자료를 꺼내 보는 유일한 창구입니다.
5. **AI 엔진** (Claude Code·Codex) — 질문에 답하고 라벨을 붙입니다.
6. **외부 API** — 논문 데이터베이스처럼 바깥에서 자료를 가져오는 창구입니다.

### 기술 한 장 정리

[표] 쓰인 기술과 쓰인 이유 | 자료: requirements.txt, README, docs
| 기술 | 무엇인가 | 왜 썼나 | 어디에 |
|---|---|---|---|
| Python | 언어(3.11 이상) | 과학 계산 도구가 가장 많음 | 전체 |
| FastAPI | 웹 서버 | 가볍고, 내 PC에서만 열기 쉬움(uvicorn으로 실행) | `app/server.py` |
| HTML·JS | 화면 | 설치 없이 브라우저로 열림 | `app/static/` |
| SQLite | 데이터베이스 | 서버 설치가 필요 없고 폴더째 백업됨. FTS5로 전문검색 | `db\rd.sqlite` |
| MCP | AI 도구 규격 | AI가 쓸 수 있는 일을 정확히 정해 줄 수 있음 | `app/mcp_server.py` |
| Claude Code | AI 엔진 | 내 PC에 로그인해 쓰는 명령창 AI. 보조 엔진은 Codex | `app/engines/` |
| PyMuPDF | PDF 읽기 | 빠름. 표가 중요하면 pdfplumber | `app/ingest/` |
| 선택 파서 | OCR·고급 파서 | RapidOCR(스캔)·Docling(2단 논문)·kordoc(한글). 모두 내 PC에서 | `parser_tools/` |
| watchdog | 폴더 감시 | 받은편지함에 파일이 들어오면 바로 처리 | `ingest/watcher.py` |
| RDKit | 분자 구조 | 인터넷 없이 그림이 그려짐. 3D는 3Dmol.js·three.js | `app/viz/` |
| statsmodels | 통계 계산 | 학술지에서 널리 쓰는 검정을 그대로 씀(scipy·matplotlib과 함께) | `app/stats/` |
| Playwright | 브라우저 조종 | 자바스크립트로 그리는 웹 목록을 읽음 | `collect/backends/` |
| pytest | 자동 시험 | 고칠 때마다 망가진 곳을 바로 찾음 | `tests/` |

표가 길지만 원리는 하나입니다. **가능하면 내 PC 안에서, 설치는 적게, 인터넷 없이도 돌게.** 이 원칙 때문에 3D 그림 라이브러리도 인터넷에서 그때그때 받지 않고, 정해진 버전(3Dmol.js 2.4.2, three.js r170)을 프로그램 폴더 안(`app/static/vendor/`)에 넣어 두었습니다. 그래서 인터넷이 끊긴 실험실 PC에서도 시각화 화면이 열립니다.

## 코드로 보는 핵심 네 가지

아래 코드는 이 프로그램의 실제 코드에서 옮겼습니다. 읽기 쉽게 자료형 표시와 일부 줄은 덜어 냈습니다. 다 이해할 필요는 없습니다. 주석(`#` 뒤의 설명)과 아래 풀이만 읽어도 충분합니다.

### 하나. AI의 손을 묶는 명령

AI 엔진(Claude Code)을 부를 때 만드는 명령입니다.

```python
def build_command(exe, role_file, write, max_turns, model=None,
                  no_builtin_tools=True):
    cmd = [exe, "-p", "--output-format", "json",
           "--mcp-config", str(mcp_config_path()), "--strict-mcp-config"]
    if no_builtin_tools:
        cmd += ["--tools", ""]  # 내장 도구(파일 읽기 포함) 없음
    cmd += ["--allowedTools", ",".join(allowed_tools(write)),
            "--disallowedTools", disallowed_tools()]
```

풀이: Claude Code는 원래 파일을 읽고, 명령을 실행하고, 웹을 검색하는 도구를 가지고 있습니다. `--tools ""`는 그 도구를 **전부 뺍니다**. 그러면 AI는 `--allowedTools`에 적은 이 앱의 도구만 쓸 수 있습니다. AI가 데이터 폴더의 원본 파일을 직접 열어 볼 길이 없어지는 것입니다. 8장의 안전장치가 바로 이 몇 줄에서 시작합니다.

### 둘. 기밀 식별 정보 가리기

AI에게 본문을 넘기기 전에 거치는 함수입니다.

```python
MASK = "[가림]"

def _mask_text(doc_id, text, ids=None):
    """기밀 자료의 식별 정보를 [가림]으로."""
    if not text:
        return text
    for v in (ids if ids is not None else _identifiers()):
        text = text.replace(v, MASK)
    return text
```

풀이: `_identifiers()`는 데이터베이스에 있는 모든 시료의 로트번호·공급처·시료번호를 모아 옵니다. 함수는 본문에서 그 글자를 찾아 `[가림]`으로 바꿉니다. 실제 코드는 긴 이름부터 바꿉니다. 짧은 이름을 먼저 바꾸면 긴 이름의 일부만 가려지고 나머지가 드러날 수 있기 때문입니다.

### 셋. 짧은 말도 찾는 검색

데이터베이스에 검색 색인을 만드는 부분입니다.

```sql
-- 전문검색: 3글자 이상은 trigram 색인, 짧은 말은 LIKE로 보완한다
CREATE VIRTUAL TABLE IF NOT EXISTS chunk_fts USING fts5(
  text, content='chunk', content_rowid='rowid', tokenize='trigram'
);
```

풀이: **trigram**은 글을 세 글자씩 겹쳐 잘라 색인하는 방법입니다. "사과박식이섬유"처럼 띄어쓰기가 없는 한국어도 찾을 수 있습니다. 대신 두 글자 이하 낱말(예: "pH", "펙틴")은 세 글자 조각이 없어 못 찾으므로, 그런 말은 `LIKE`라는 단순 비교로 따로 찾습니다. 찾은 결과의 순서는 간단한 점수로 정합니다. 넓힌 동의어가 본문에 몇 번 나오는지 더하고, 표준 이름이나 원문 표기에는 가중치를 더 줍니다.

### 넷. 출처가 달라도 같은 모양으로

논문을 가져오는 출처는 열 곳이 넘습니다. 출처마다 돌려주는 모양이 다르므로, 하나의 모양으로 맞춥니다.

```python
@dataclass
class Item:
    """정규화된 수집 결과 한 건."""
    source: str                 # 출처 key (예: "openalex")
    source_id: str              # 그 출처 안의 고유 ID
    title: str
    doi: str | None = None      # 소문자, "10." 으로 시작
    authors: list[str] = field(default_factory=list)
    year: int | None = None
    pdf_url: str | None = None  # 오픈 액세스 원문 PDF(있을 때만)
```

풀이: 어느 출처에서 왔든 제목·DOI·저자·연도는 같은 칸에 들어갑니다. 그래서 같은 논문이 두 출처에서 와도 DOI로 비교해 하나로 합칠 수 있습니다. 원문 PDF 칸은 **누구나 무료로 볼 수 있는 논문(오픈 액세스)일** 때만 채웁니다.

이 네 가지는 말로만 약속한 것이 아닙니다. 자동 시험이 지킵니다. 가짜 Claude Code 프로그램을 만들어 명령이 제대로 꾸려지는지 보고, 기밀 자료가 가려지거나 막히는지 보고, 같은 논문이 하나로 합쳐지는지 봅니다. 누군가 코드를 고치다 안전장치를 실수로 빼면 시험이 바로 실패합니다. 그래서 AI에게 새 기능을 맡길 때도 안심하고 맡길 수 있습니다. 시험은 프로그램 폴더의 `tests` 폴더에 있고, 4장의 표에 적은 시험 개수가 바로 이 시험들의 수입니다.

### AI 역할 지침은 그냥 글이다

AI에게 "너는 라벨러다"라고 알려 주는 지침은 코드가 아니라 평범한 글(마크다운 파일)입니다. 데이터 폴더의 `agents` 폴더에 다섯 개가 있습니다(라벨러·자료 사서·성분 분석가·검증자·리포트 작성자). 라벨러 지침의 한 부분은 이렇습니다.

```text
## 규칙
- surface는 본문에 있는 글자를 그대로 복사합니다(띄어쓰기 포함).
- 수치는 본문에 있는 숫자만. 계산하거나 단위를 환산하지 않습니다.
- confidence는 솔직하게: 확실 0.9 이상, 해석이 필요 0.6~0.9,
  애매하면 넣지 않습니다.
- [가림]은 기밀 식별 정보입니다. 추측하지 않습니다.
```

이 파일은 직접 고쳐도 됩니다. 우리 연구실만의 규칙이 있다면 여기에 한 줄 더 쓰면 AI가 그 규칙을 따릅니다. 코드를 몰라도 AI의 행동을 바꿀 수 있는 곳입니다. 고친 뒤에는 예시 자료로 AI 라벨을 한 번 돌려 보고, 라벨 검토에서 결과가 원하는 대로 바뀌었는지 확인하세요. 지침을 고쳤으면 결과도 내 눈으로 확인한다는 4장의 원칙이 여기서도 같습니다. 프로그램을 새 버전으로 바꿔도, 사용자가 고친 지침은 덮어쓰지 않습니다. 고치지 않은 지침만 새 버전으로 자동 갱신됩니다.

::: info 알아 두기
데이터베이스에는 표가 39개 있습니다. 처음(M1)에는 30개였고, 수집·실험이 붙으며 36개, 작업대 기능이 붙으며 39개가 되었습니다. 표 이름은 나중에 팀용 프로그램으로 옮길 수 있게 팀판과 같은 이름을 씁니다. 개인용으로 시작해도 나중에 버리지 않고 이어 쓸 수 있게 설계한 것입니다. 작게 시작하되 다음 단계를 막지 않는 것, 이것도 AI에게 설계를 맡길 때 조건으로 말해 두면 좋은 내용입니다.
:::

::: info 핵심 정리
- 층은 화면 → 서버 → 데이터베이스 → MCP 창구 → AI 엔진 → 외부 API 순입니다.

- `--tools ""` 한 줄이 AI를 앱의 도구 안에 가두고, `[가림]` 함수가 기밀 식별 정보를 지웁니다.
:::
