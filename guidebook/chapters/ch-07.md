# 개발 도구와 클라우드

AI와 무언가를 만들기 시작하면 이 이름들을 자주 듣게 됩니다. git, GitHub, Vercel, Neon, Supabase, Cloudflare. 이 장에서는 각 도구가 무엇인지, **이 프로젝트에서 실제로 썼는지**, 그리고 간단한 사용법을 봅니다. 쓰지 않은 도구는 쓰지 않았다고 분명히 적었습니다.

## 도구 여섯 가지 한눈에

![이 프로젝트와 개발 도구·클라우드의 관계](i16-dev-cloud-map.png "출처: 송창민 작성")

이 앱(R&D Studio V0.5)은 **내 PC에서만** 돕니다. 파이썬 프로그램과 SQLite 데이터베이스가 PC 안에 있고, 변경 기록은 git이 남기며, 그 기록을 GitHub의 비공개 저장소에 올려 둡니다. 따로 연결해 쓰는 식품 영양 DB(식품 MCP)는 옆 프로젝트로, 서버는 Vercel에, 데이터는 Neon에 있습니다. Supabase와 Cloudflare는 이 앱에서 쓰지 않습니다.

|---|---|---|---|
| git | 코드 변경 기록(저장 지점) | 씀 — 커밋 5번 | 코드를 고칠 때마다 |
| GitHub | git 기록을 올려 두는 인터넷 저장소 | 씀 — 비공개 저장소 | 백업·다른 PC·협업 |
| Neon | 인터넷에 있는 Postgres 데이터베이스 | 간접 — 식품 MCP의 데이터 | 여러 곳에서 같은 DB를 쓸 때 |
| Vercel | 웹앱을 인터넷에 올려 주는 곳 | 간접 — 식품 MCP 원격 서버 | 웹 서비스를 공개할 때 |
| Supabase | DB·로그인·파일 저장을 묶은 서비스 | 쓰지 않음 | 팀용 버전을 만든다면 |
| Cloudflare | 도메인·CDN·보안·작은 서버 | 쓰지 않음 | 공개 사이트를 빠르고 안전하게 |

### git — 저장 지점을 남기는 도구

**git**은 파일이 어떻게 바뀌어 왔는지 기록하는 도구입니다. 게임의 저장 지점처럼, "여기까지 잘 됐다"는 순간을 **커밋**으로 남겨 두면 언제든 그 상태를 다시 보거나 되돌릴 수 있습니다.

이 프로젝트의 실제 커밋 목록은 다섯 줄입니다(`git log --oneline`).

```text
cd17ad4 M3-2: 크롤러 엔진(직접·브라우저·Apify), 파서 도구 선택, 문서 작업대(청킹·라벨 학습), 통계 분석
96b62c7 M3: 자료 수집(공식 API·크롤러·수집함) + 내 실험(공정 흐름 편집·내 데이터·예측 비교·보정)
5399ec0 M2 완료 + 시각화: 라벨 일괄 처리·CoA·Codex·OCR, 건조 설비 3D·P&ID, 근거 기반 건조 결과 예측
92a7ea1 식품 영양 DB(ByOrbit Food MCP) 연결 — 선택 기능
4db41c5 ByOrbit R&D Studio 개인용 M1 + 기밀 자료 유출 경로 차단
```

커밋 메시지에 예전 이름이 남아 있는 것은 기록이기 때문입니다. 기록은 고치지 않습니다. 그리고 4장에서 본 대로, AI는 사람이 요청했을 때만 커밋했습니다.

**간단한 사용법**

```powershell
git init                      # 이 폴더를 git으로 관리 시작(처음 한 번)
git status                    # 무엇이 바뀌었나 보기
git diff                      # 바뀐 줄 자세히 보기
git add 파일이름               # 저장할 파일 고르기
git commit -m "무엇을 왜 바꿨는지"   # 저장 지점 남기기
git log --oneline             # 지금까지의 저장 지점 목록
```

**.gitignore**는 "이 파일은 기록하지 마"라는 목록입니다. 이 프로젝트는 데이터베이스(`*.sqlite`), 비밀 값 파일(`.env*`), 가상환경(`.venv/`)을 여기에 넣어 실수로 올라가지 않게 했습니다. **.gitattributes**에는 Windows 배치 파일(`.bat`)의 줄바꿈을 CRLF로 고정하라고 적었습니다. 줄바꿈이 바뀌면 install.bat의 한글 줄이 깨져 명령처럼 실행되는 문제가 있었기 때문입니다.

### GitHub — 기록을 올려 두는 저장소

**GitHub**은 git 기록을 인터넷에 올려 두는 곳입니다. PC가 고장 나도 코드가 남고, 다른 PC에서 내려받을 수 있습니다. 이 프로젝트는 **비공개 저장소**를 씁니다. 비공개 저장소는 내가 초대한 사람만 볼 수 있습니다. 연구 도구의 설계와 기밀 처리 방식을 아무에게나 보여 줄 이유가 없기 때문입니다.

**간단한 사용법**

GitHub 공식 명령줄 도구 `gh`를 쓰면 짧습니다.

```powershell
gh auth login                                          # 처음 한 번 로그인
gh repo create 저장소이름 --private --source . --push   # 비공개 저장소를 만들고 올리기
git push                                               # 새 커밋 올리기
git pull                                               # 다른 PC에서 받은 변경 가져오기
```

::: warn 주의
키와 비밀번호는 절대 커밋하지 않습니다. 이 앱의 규칙은 "API 키는 환경 변수로만"입니다. `.env` 같은 파일은 .gitignore에 넣고, 설정 파일·코드·문서에 키 값을 쓰지 않습니다. 한 번 올라간 키는 비공개 저장소라도 새 키로 바꾸는 것이 안전합니다. 기록에 남아 지워도 다시 찾을 수 있기 때문입니다.
:::

### Neon — 인터넷에 있는 데이터베이스

**Neon**은 Postgres라는 데이터베이스를 인터넷에서 빌려 쓰는 서비스입니다. 서버를 직접 관리하지 않아도 되고, 여러 곳에서 같은 데이터를 함께 씁니다.

이 앱 자체는 Neon을 쓰지 않습니다. 이 앱의 데이터베이스는 내 PC의 파일 하나(SQLite, `db\rd.sqlite`)입니다. 이유는 세 가지입니다. 한 사람이 쓰는 **개인용**이고, CoA 같은 **기밀** 자료가 PC 밖으로 나가면 안 되고, 인터넷이 끊겨도(**오프라인**) 돌아야 하기 때문입니다.

Neon은 옆 프로젝트인 **식품 MCP** (ByOrbit Food MCP)에서 씁니다. 농진청 원물·식약처 식품 성분 데이터가 Neon의 Postgres에 들어 있습니다. 설정에서 식품 영양 DB 연결을 켜면, 식품 MCP가 그 DB에 묻습니다. DB 접속 주소(`DATABASE_URL`)는 식품 MCP 프로젝트의 `.env.local`에만 있고, 이 앱은 그 파일을 읽지 않습니다.

**간단한 사용법**

1. Neon 콘솔에서 프로젝트를 만듭니다.
2. 접속 주소(connection string)를 복사합니다. `postgresql://사용자:비밀번호@주소/DB이름?sslmode=require` 꼴입니다.
3. 그 주소를 환경 변수 `DATABASE_URL`에 넣습니다.
4. 명령줄 도구 psql이나 프로그램의 DB 드라이버로 접속합니다.

```powershell
psql "$env:DATABASE_URL"        # PowerShell에서 환경 변수로 접속
```

### Vercel — 웹앱을 인터넷에 올리는 곳

**Vercel**은 만든 웹앱을 인터넷에 올려(배포해) 누구나 주소로 열 수 있게 해 주는 서비스입니다. 코드를 올리면 서버 준비를 대신해 줍니다.

식품 MCP의 원격 서버(Next.js로 만든 웹앱)가 Vercel에 올라가 있습니다. 식품 MCP 문서에 따르면 서울 리전에 배포되어 있습니다. 그래서 다른 PC의 Claude도 식품 MCP 원격 주소로 접속할 수 있습니다.

이 앱은 Vercel에 올리지 않습니다. 이 앱은 일부러 내 PC 주소(127.0.0.1)에서만 열리도록 만든 파이썬 프로그램입니다(8장).

**간단한 사용법**

```powershell
npm i -g vercel           # 명령줄 도구 설치
vercel login              # 로그인
vercel                    # 미리보기 배포(시험용 주소)
vercel --prod             # 실제 배포
vercel env add 이름        # 서버에 환경 변수(비밀 값) 넣기
```

비밀 값은 코드에 쓰지 않고 `vercel env add`로 서버에만 넣습니다.

### Supabase — 이 앱에서는 쓰지 않음

**Supabase**는 Postgres 데이터베이스에 로그인(Auth), 파일 저장(Storage)까지 묶어 주는 서비스입니다. 여러 사람이 로그인해서 같은 자료를 쓰는 **팀용 버전**을 만든다면 후보가 될 수 있습니다. 이 앱의 표 이름을 팀판과 같게 맞춰 둔 것(5장)도 그런 확장을 막지 않으려는 것입니다. 하지만 지금 이 앱에서는 쓰지 않습니다.

**간단한 사용법**

1. Supabase 콘솔에서 프로젝트를 만들고 프로젝트 주소(URL)와 키를 확인합니다.
2. 키는 두 종류입니다. 화면(브라우저)에 넣어도 되는 **공개용 키** (anon, 새 이름 publishable)와, 서버에만 두어야 하는 **비밀 키** (service_role, 새 이름 secret)입니다.
3. 명령줄 도구로 내 PC에서 시험하고 표 구조(마이그레이션)를 관리합니다.

```powershell
npx supabase init                   # 이 폴더에 Supabase 설정 만들기
npx supabase start                  # 내 PC에서 시험용으로 띄우기(Docker 필요)
npx supabase migration new 표만들기   # 표 구조 변경 파일 만들기
```

### Cloudflare — 이 앱에서는 쓰지 않음

**Cloudflare**는 인터넷의 길목을 맡는 서비스입니다. 도메인 주소 관리(DNS), 전 세계에 사본을 두어 빠르게 보여 주기(CDN), 공격 막기, 작은 서버(Workers)와 정적 사이트(Pages), 파일 저장소(R2), 내 PC를 인터넷에 이어 주는 터널(Tunnel)까지 있습니다. 공개 웹사이트를 운영한다면 유용합니다. 하지만 이 앱에서는 쓰지 않습니다.

**간단한 사용법**

```powershell
npx wrangler login                  # 명령줄 도구로 로그인
npx wrangler pages deploy ./dist    # 정적 사이트 폴더를 Pages에 올리기
```

::: warn 주의
이 앱을 터널 등으로 인터넷에 여는 것은 권하지 않습니다. 이 앱에는 로그인이 없고, 일부러 127.0.0.1·localhost 주소로 온 요청만 받도록 만들었습니다. 밖에서 열리게 하면 기밀 자료가 든 화면을 아무나 볼 수 있게 됩니다. 다른 사람과 함께 쓰려면 앱을 인터넷에 여는 대신, 로그인과 권한이 있는 팀용 버전을 따로 설계해야 합니다.
:::

### AI에게 이 도구들을 맡길 때

AI 코딩 도구는 이 명령들을 대신 실행할 수 있습니다. 그래서 오히려 사람이 정해 줘야 할 것이 있습니다.

- **커밋·올리기·배포는 요청할 때만.** "내가 확인한 뒤에 커밋해 줘", "배포는 하지 마"처럼 분명히 말합니다.
- **비공개로.** 저장소를 만들 때 `--private`를 조건으로 줍니다.
- **키는 환경 변수로만.** "키 값을 파일이나 커밋에 쓰지 마"를 조건에 넣습니다.
- **쓰지 않을 클라우드는 쓰지 않는다고.** "이 앱은 내 PC 안에서만 돌아야 해"라는 조건 한 줄이 불필요한 배포와 노출을 막습니다.

### git으로 되돌리고 비교하기

git의 진짜 쓸모는 "어제는 잘 됐는데 오늘은 안 된다"일 때 나옵니다. 자주 쓰는 명령은 이렇습니다.

```powershell
git diff                     # 마지막 커밋 뒤에 바뀐 줄 보기
git diff HEAD~1 HEAD         # 바로 앞 커밋과 마지막 커밋 비교
git show cd17ad4 --stat      # 그 커밋에서 바뀐 파일 목록
git restore 파일이름          # 커밋하지 않은 그 파일의 변경 버리기
```

`git restore`는 커밋하지 않은 변경을 지우므로 되살릴 수 없습니다. 쓰기 전에 `git diff`로 무엇이 사라지는지 먼저 봅니다. 기록 자체를 지우는 명령(`git reset --hard`, 강제 push 등)은 AI에게 맡기지 말고, 꼭 필요하면 사람이 직접 확인한 뒤 실행합니다. 이 프로젝트에서도 AI는 이런 명령을 쓰지 않도록 막아 두고 일했습니다.

되돌릴 일이 생겨도 당황하지 않으려면, 기능 하나를 끝낼 때마다 작게 커밋해 두는 것이 가장 좋은 보험입니다. 이 프로젝트도 단계(M1·M2·M3)가 끝날 때마다 커밋했기 때문에, 문제가 생기면 어느 단계에서 생겼는지 바로 좁힐 수 있었습니다. 커밋 메시지에 "무엇을, 왜" 바꿨는지 한두 줄로 남기는 것도 잊지 않습니다. 몇 달 뒤의 나에게 쓰는 메모라고 생각하면 됩니다. 메시지만 읽어도 그날 무엇을 했는지 떠오르게 쓰는 것이 목표입니다. 이 책 7장의 커밋 목록이 그런 예입니다. 한 줄만 읽어도 그 단계에서 무엇이 들어갔는지 알 수 있습니다.

::: info 핵심 정리
- git은 저장 지점, GitHub은 그것을 올려 두는 비공개 저장소입니다. 이 프로젝트는 둘 다 씁니다.
- 식품 MCP는 Vercel(서버)과 Neon(DB)을 쓰지만, 이 앱 자체는 내 PC의 SQLite로만 돕니다.
- Supabase와 Cloudflare는 쓰지 않습니다. 이 앱을 인터넷에 여는 것은 권하지 않습니다.
:::
