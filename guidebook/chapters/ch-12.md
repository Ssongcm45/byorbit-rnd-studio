# 측정값과 AI에 묻기

라벨을 승인하면 수치가 한 곳에 모입니다. 이제 그 수치를 표로 보고, AI에게 질문을 던져 봅시다. 이 장은 2장의 "수치 찾기"와 "반복 정리" 고민에 대한 답입니다.

### 측정값 화면

왼쪽 메뉴의 **측정값**을 누르면 두 종류의 값이 한 표에 보입니다.

- CoA 엑셀에서 바로 읽은 값
- 논문·보고서에서 AI가 찾고 사람이 승인한 값

![측정값 — 항목 "식이섬유"로 조회. 근거 칸의 CoA 열기·근거 청크(승인한 논문 값은 예시 라벨에서 온 것)](s04a-measurements.png "출처: R&D Studio V0.5 화면(예시 데이터)")

표의 칸은 부산물·항목·값·단위·기준·전처리·시험법·시료·입력·출처입니다. "입력" 칸은 값이 CoA에서 왔는지, 사람이 승인한 추출값인지 알려 줍니다. 맨 끝 **근거** 칸의 단추로 바로 원문을 엽니다. CoA 값은 **CoA 열기**, 논문에서 승인한 값은 **근거 청크**입니다. 숫자 하나하나가 **어디서 왔는지** 따라갈 수 있다는 점이 엑셀 정리와 가장 다른 점입니다.

이 화면은 내 PC 전용이라 로트번호·공급처가 그대로 보입니다. AI에 넘길 때만 가려집니다.

**건량**은 물을 뺀 무게 기준, **습량**은 물을 포함한 무게 기준입니다. 같은 시료라도 건량 기준 값이 더 큽니다. 서로 다른 기준의 값을 그대로 비교하면 안 되므로, 표에 기준이 따로 적혀 있습니다.

::: tip 따라 해 보기
1. **측정값**의 항목 칸에 "식이섬유"를 넣고 **조회**를 누릅니다.
2. 전처리 칸을 보며 동결건조 시료와 열풍건조 시료의 값을 비교해 봅니다.
3. **CSV 저장**을 눌러 엑셀에서 엽니다. 보고서에 붙일 표가 바로 생깁니다.
:::

CoA의 건조 정보는 "열풍건조; 60 ℃; 12 h"처럼 한 줄 형식으로 저장됩니다. 이 형식 덕분에 14장의 건조 예측이 내 CoA 값을 보정 근거로 쓸 수 있습니다.

### AI에 묻기

왼쪽 메뉴의 **AI에 묻기**는 이 도구의 얼굴입니다. 질문을 쓰면 Claude Code가 내 자료함을 찾아보고, **출처를 달아** 답합니다.

![AI에 묻기 — 질문, 역할, Anthropic 전송 안내와 묻기 단추(아직 보내지 않음)](s06a-ask.png "출처: R&D Studio V0.5 화면(예시 데이터)")

### 역할 고르기

질문칸 옆에서 AI의 **역할**을 고릅니다. 역할마다 일하는 지침(5장의 `agents` 폴더 파일)이 다릅니다.

[표] AI에 묻기의 세 역할 | 자료: app/static/index.html, agents 폴더
| 역할 | 이런 때 고르세요 | 결과 |
|---|---|---|
| 자료 사서 | "사과박 건조 관련 자료가 뭐가 있지?" | 관련 자료와 청크를 찾아 정리 |
| 성분 분석가 | "동결건조와 열풍건조의 TPC 차이는?" | 측정값을 비교하고 근거를 붙여 설명 |
| 리포트 작성자 | "사과박 식이섬유 소재화 현황 보고서 초안" | 근거 번호가 달린 초안을 `reports` 폴더에 저장 |

### 좋은 질문 쓰기

4장에서 본 네 재료가 여기서도 통합니다. 질문에 목적·조건·결과물·확인 방법을 담으면 답이 훨씬 좋아집니다.

- 나쁜 예: "사과박 알려줘"
- 좋은 예: "사과박을 열풍건조할 때 온도에 따라 총폴리페놀이 얼마나 줄어드는지, 내 자료함의 측정값과 논문만 근거로 정리해 줘. 표로 보여 주고, 값마다 출처 번호를 달아 줘. 근거가 없는 부분은 '자료 없음'이라고 써 줘."

마지막 문장이 중요합니다. "모르면 모른다고 하라"는 조건을 주면, AI가 빈자리를 그럴듯한 말로 채우는 일이 줄어듭니다.

묻기 단추 옆에는 "질문과 가려진 본문 일부가 Anthropic으로 전송됩니다"라는 안내가 늘 보입니다. 질문을 쓴 뒤 Ctrl+Enter로도 보낼 수 있습니다.

::: warn 주의
AI에 묻는 순간 질문과, AI가 도구로 꺼내 본 본문 일부가 Anthropic으로 전송됩니다. 기밀 자료는 CoA 규칙에 따라 식별 정보가 가려지거나 아예 빠집니다(8장). 질문 문장 자체에 공급처 이름이나 로트번호를 쓰지 마세요. 질문은 가림 대상이 아닙니다.
:::

### 답을 확인하는 습관

답 아래의 출처 표시를 누르면 그 원문 청크가 열립니다. 꼭 열어 보세요. 리포트 초안은 이 화면 아래쪽 리포트 목록에서 열면 근거마다 **원문** 링크가 붙어 있습니다. 확인할 것은 두 가지입니다.

1. 원문에 정말 그 숫자가 있는가?
2. 조건(온도·시간·기준)이 질문과 같은가?

### 명령창에서 묻기

프로그램 폴더의 PowerShell에서도 같은 일을 할 수 있습니다.

```powershell
.venv\Scripts\python -m app.cli search "사과 포마스 식이섬유"
.venv\Scripts\python -m app.cli ask "열풍건조 온도별 TPC 차이를 정리해 줘"
```

Claude Code 대화창에 이 자료 서버를 직접 붙여 쓸 수도 있습니다. 이때도 AI가 쓸 수 있는 도구는 앱과 같은 7개(자료 찾기·청크 읽기·개념 찾기·측정값 묻기·라벨 저장·리포트 초안 저장·새 개념 제안)뿐입니다.

**식품 영양 DB 연결**을 켜면 AI가 부산물의 측정 성분을 농촌진흥청 원물·식약처 식품 성분 DB의 기준값과 견줘 볼 수 있습니다. 이때 식품명과 성분값이 그 DB로 질의됩니다. 두 번째 AI인 **Codex 엔진**도 같은 도구와 같은 CoA 규칙으로 돌고, 데이터 폴더 파일을 직접 읽지 못하는 것을 실제 시험으로 확인했습니다.

같은 질문을 역할만 바꿔 다시 물어보는 것도 좋은 습관입니다. 자료 사서로 먼저 "무엇이 있는지"를 보고, 성분 분석가로 "숫자가 어떻게 다른지"를 묻고, 마지막에 리포트 작성자로 초안을 받으면 근거를 한 번 더 걸러 보게 됩니다.

리포트 초안은 데이터 폴더의 `reports` 폴더에 마크다운 파일로도 남습니다. 워드 문서로 옮길 때는 근거 번호를 지우지 말고 각주나 참고문헌으로 바꿔 두면, 나중에 누가 숫자의 출처를 물어도 바로 답할 수 있습니다. 초안을 고칠 때도 근거 번호가 붙은 문장의 숫자는 원문과 다시 맞춰 봅니다. AI가 쓴 문장을 사람이 고치면, 그 문장의 근거도 함께 바뀌었는지 확인해야 하기 때문입니다. 근거가 사라진 문장은 지우거나 "확인 필요"라고 표시해 둡니다.

::: info 핵심 정리
- 측정값 표는 CoA 값과 승인한 값을 함께 보이고, 값마다 출처 파일을 보여 줍니다.
- AI에 묻기는 자료 사서·성분 분석가·리포트 작성자 중 역할을 골라 출처 달린 답을 받습니다.
- 질문에 "근거가 없으면 자료 없음이라고 써라"를 넣고, 출처는 꼭 원문으로 확인합니다.
- 리포트 초안은 reports 폴더에 남고, 고칠 때도 근거 번호와 원문을 다시 맞춰 봅니다.
:::
