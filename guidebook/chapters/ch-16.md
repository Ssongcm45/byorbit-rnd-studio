# 통계 분석과 논문용 결과

실험 데이터가 모이면 결국 묻게 됩니다. "온도가 정말 수율에 영향을 줬나? 산 종류에 따라 차이가 있나?" **통계 분석** 메뉴는 이 질문에 통계로 답하고, 논문에 바로 넣을 표와 그림까지 만들어 줍니다. 이 기능은 4장에서 본 이 요청에서 나왔습니다.

> "수율에 온도·반응 시간·산 종류가 주는 영향을 회귀분석하고, 산 종류별 수율 차이를 t검정해 줘…"

### 분석 한 바퀴

![분석 흐름 — 데이터에서 재현 파일까지](i11-stats.png "출처: 송창민 작성")

데이터를 고르고, 회귀분석과 t검정을 돌리고, 가정을 점검하고, 표 1·그림 1·해석 세 문장을 받고, 같은 숫자를 Python·R·Stata로 다시 낼 수 있는 파일을 받습니다. 모든 계산은 이 PC 안에서만 합니다.

### 먼저 낱말 다섯 개

통계가 처음이라면 이 다섯 낱말만 알면 됩니다.

- **회귀분석** — 여러 조건(온도·시간·산 종류)이 결과(수율)에 각각 얼마나 영향을 주는지 한꺼번에 재는 방법
- **t검정** — 두 집단(예: 구연산과 염산)의 평균이 우연이 아닌 차이인지 따지는 방법
- **p값** — "사실은 차이가 없는데 우연히 이만큼 차이가 날 확률". 보통 0.05보다 작으면 "유의하다"고 씁니다
- **R²** — 모형이 결과의 흔들림을 얼마나 설명하는지(0~1). 1에 가까울수록 잘 설명합니다
- **95% 신뢰구간(CI)** — 진짜 값이 있을 법한 범위

### 1. 데이터 고르기와 변수 역할

![통계 분석 — 예시(가짜) 데이터 고르기와 데이터 미리보기](s13a-stats-setup.png "출처: R&D Studio V0.5 화면(예시 데이터)")

![변수 역할 아래쪽 — 모형 항(교호작용·2차항)과 그림 1 가로축](s13b-stats-terms.png "출처: R&D Studio V0.5 화면(예시 데이터)")

데이터는 세 곳에서 고릅니다.

1. **내 실험** — 15장의 런 하나가 한 행이 됩니다. 추출 단계의 **산 종류**·**용매 종류**와 건조 단계의 **건조 방식**은 자동으로 범주 변수가 됩니다. 예전처럼 런 비고에 `산=구연산`이라고 적은 것도 그 런의 조건 칸이 비었을 때 읽습니다.
2. **파일** — CSV나 XLSX. 열 이름으로 형식을 짐작하고, 열 대응에서 고칩니다.
3. **예시** — 사과박 펙틴 산 추출 수율. **가짜(모의) 데이터**입니다.

그다음 변수 역할을 정합니다. 결과(수율), 연속 설명 변수(온도·시간), 범주 설명 변수(산 종류)와 기준 수준(예: 구연산), 그리고 t검정 종류(기본은 Welch)입니다.

그 아래 **모형 항(선택 — 기본은 주효과만)** 칸에서 두 가지를 더할 수 있습니다. **교호작용** (예: 추출 온도 × 산 종류 — 온도의 효과가 산마다 다른가)과 연속 변수의 **2차항** (예: 추출 온도² — 효과가 곡선인가)입니다. 항을 늘리면 계수 하나당 런 수가 줄어드므로 표본 크기 점검을 함께 봅니다. **그림 1 가로축**에서는 그림 1(a)의 가로축으로 쓸 연속 변수를 고릅니다(기본은 온도).

::: tip 따라 해 보기
1. 왼쪽 메뉴에서 **통계 분석**을 누르고 데이터로 **예시 (가짜)** 단추를 고릅니다.
2. 결과에 수율, 연속 변수에 온도와 시간, 범주 변수에 산 종류를 둡니다.
3. **분석 실행**을 누릅니다. 화면과 표·그림에 "예시(모의) 데이터"가 찍혀 있는지 확인합니다.
:::

### 2. 결과 읽기 — 가정 점검이 먼저

![분석 결과 — 예시(모의) 데이터 경고, 해석 세 문장, 표 1 미리보기](s14a-stats-head.png "출처: R&D Studio V0.5 화면(예시 데이터)")

![가정 점검 카드](s14b-stats-checks.png "출처: R&D Studio V0.5 화면(예시 데이터) | width: 95%")

결과 화면의 맨 위는 **가정 점검** 카드입니다. 통계 방법마다 "이런 조건일 때만 믿을 수 있다"는 가정이 있습니다. 앱은 그 가정을 하나씩 검사해 **통과·주의·실패·설계로 판단**으로 표시하고, 검정 이름과 기준값을 함께 보여 줍니다.

[표] 주요 가정 점검 | 자료: docs/STATS.md
| 점검 | 무엇을 보나 | 통과 기준 |
|---|---|---|
| 잔차 정규성 | 오차가 종 모양으로 퍼졌나(Shapiro–Wilk) | p ≥ .05 |
| 등분산 | 오차 크기가 고르게 퍼졌나(Breusch–Pagan) | p ≥ .05. 어기면 강건 표준오차(HC3)로 바꿈 |
| 다중공선성 | 설명 변수끼리 너무 닮지 않았나(VIF) | 5 이하 |
| 영향점 | 혼자 결과를 크게 흔드는 런이 있나(Cook's D) | 4/n 넘는 런을 이름으로 보여 줌 |
| 표본 크기 | 런이 충분한가 | 설명 계수 하나당 10개 이상 |

앱은 작은 표본에서 "검정이 유의하지 않음"을 "가정이 맞음"으로 단정하지 않습니다. 표본이 작으면 "검정력이 낮아 위반 없음을 보장하지 않는다"는 말을 붙입니다.

### 3. 예시 데이터의 실제 결과

예시(모의) 데이터로 실행하면 앱이 아래 해석 세 문장을 만듭니다. 이 문장은 AI가 쓴 것이 아니라 **계산 결과로만 채우는 틀 문장**입니다. 그래서 숫자가 바뀌어도 문장이 지어낸 말을 하지 않습니다.

1. 추출 온도·추출 시간·산 종류를 넣은 회귀 모형은 펙틴 수율 변동의 73%를 설명했다(R² = 0.73, 수정 R² = 0.71, F(3, 49) = 43.95, p < 0.001, n = 53).
2. 추출 온도가 1 ℃ 증가할 때마다 펙틴 수율은 0.173%p씩 증가했고(B = 0.173, 95% CI [0.137, 0.209], p < 0.001), 추출 시간의 효과는 유의하지 않았다(B = −0.0005, 95% CI [−0.0124, 0.0115], p = 0.939).
3. 염산은 구연산보다 펙틴 수율이 1.76%p 높았으며(M ± SD 15.73 ± 1.80% 대 13.97 ± 1.73%, Welch t(51.0) = 3.63, p < 0.001, Hedges' g = 0.98), 추출 온도·추출 시간을 보정한 회귀에서도 차이가 유지되었다(B = 1.69, 95% CI [1.11, 2.27], p < 0.001).

::: stat
R² = 0.73
예시(모의) 데이터에서 회귀 모형이 설명한 펙틴 수율 변동의 비율
:::

세 번째 문장에 숫자가 두 개 나오는 데 주목하세요. t검정의 차이(1.76%p)는 온도·시간을 무시한 단순 평균 차이이고, 회귀의 차이(1.69%p)는 온도·시간을 같게 놓았을 때의 차이입니다. 앱은 두 값을 나란히 보여 주고 차이가 나는 이유를 설명합니다.

### 5. 다른 프로그램으로 다시 내기

심사자가 "이 숫자를 어떻게 냈나요?"라고 물으면 재현 파일을 건네면 됩니다. R에서는 이 한 줄이 핵심입니다.

```r
lm(yield_pct ~ temp_c + time_min + acid)
```

Stata에서는 이렇게 씁니다.

```text
regress yield_pct temp_c time_min ib1.acid_f
```

Python 스크립트(`analysis.py`)는 앱의 계산 코드를 그대로 넣은 것이라, 같은 버전이면 같은 숫자가 나옵니다. 시험에서 실제로 실행해 차이가 1e-8보다 작은 것을 확인했습니다.

::: warn 주의
R·Stata 스크립트는 이 PC에 R·Stata가 없어 **실행해 보지 않았습니다**. 표준 명령만 써서 보수적으로 만들었습니다. 처음 돌릴 때 묶음 안의 `app_results.json` (앱이 낸 숫자)과 꼭 비교하세요. t검정 부호처럼 프로그램마다 표기가 다른 곳은 docs/STATS.md에 정리되어 있습니다.
:::

### 논문에 옮기기 전에 확인할 것

1. 화면·표·그림에 "예시(모의) 데이터"가 찍혀 있지 않은가? 찍혀 있다면 내 데이터가 아닙니다.
2. 가정 점검에 실패 카드가 없는가? 있다면 해석 문장에 붙은 단서를 그대로 옮깁니다.
3. 뺀 런(결측)의 수와 이유를 방법 문장과 표 주석에 적었는가?
4. 교호작용·2차항을 넣었다면, 넣은 이유를 연구 질문으로 설명할 수 있는가?
5. R·Stata로 다시 낸 숫자를 `app_results.json`과 맞춰 보았는가?

처음 몇 번은 예시 데이터로 결과 화면을 충분히 익힌 뒤, 내 실험 데이터로 넘어가면 덜 헷갈립니다. 예시 데이터의 결과는 이 장 3절의 숫자와 같으니, 화면과 책을 나란히 놓고 맞춰 보며 읽는 연습을 할 수 있습니다. 숫자가 같다면, 같은 앱으로 같은 계산을 다시 낼 수 있다는 뜻이기도 합니다. 재현할 수 있는 결과가 심사에서도 가장 설득력이 큽니다.

::: info 핵심 정리
- 회귀분석은 조건별 영향을, t검정은 두 집단 차이를 봅니다. 결과보다 가정 점검을 먼저 봅니다.
- 해석 세 문장은 계산값으로만 채운 틀 문장이고, 표 1·그림 1은 학술지 형식입니다.
- 재현 패키지로 Python·R·Stata에서 같은 숫자를 다시 낼 수 있습니다(R·Stata는 미실행).
- 논문에 옮기기 전에 예시 표시·가정 점검·결측·추가 항·재현 숫자를 확인합니다.
:::
